# SFT 数据质量与训练调度：Gold 起步、Silver 扩量、精品收尾

## 核心结论

SFT 中的“先用少量高质量数据起步”和“最后用精品数据收尾”并不矛盾，因为它们描述的是两个不同过程：

- **数据集建设和实验迭代**：从约 1K 条 Gold 数据出发，快速建立基线，再按评测结果扩充。
- **最终模型的训练调度**：先用大量达到正确性门槛的数据扩展覆盖，Gold 全程保留，末期提高 Gold 和困难样本权重。

如果必须把数据分阶段喂给同一个模型，通常“规模较大的合格数据在前，少量精品数据在后”比“精品在前、噪声在后”更稳妥。但最佳实践不是简单的“先低后高”，而是让精品数据贯穿训练，并在末期上采样。

## 两种顺序不要混为一谈

### 数据工程顺序

    构建 1K Gold
      -> 从 Base Model 训练小规模基线
      -> 暴露能力缺口和数据问题
      -> 清洗、补齐并扩大数据
      -> 重复独立实验与评测

这里的“从 1K 起步”通常意味着训练多组可比较的实验：

    实验 A：Base -> 1K Gold
    实验 B：Base -> 1K Gold + 4K 新增合格数据
    实验 C：Base -> 更大规模的清洗和配平数据

它不必意味着让同一个 checkpoint 先吃完 Gold，再继续吃越来越差的数据。

### 单模型训练顺序

    大规模 Silver + 持续混入 Gold
      -> 提升任务和场景覆盖
      -> 降低学习率
      -> 提高 Gold、困难样本和失败案例比例
      -> 校准最终行为

较晚的数据仍会持续影响模型参数。如果最后只训练大量错标、冲突或格式混乱的数据，可能稀释甚至覆盖先前由精品数据形成的行为。

## “低质量”必须拆成三类

| 数据情况 | 处理方式 |
|---|---|
| 表达不够精致，但答案基本正确 | 可作为 Silver 扩大覆盖 |
| 简单、重复或信息密度低 | 去重、降权、调整任务配比 |
| 答案错误、标注冲突、逻辑错误、格式非法 | 删除，不应指望末期 Gold 修复 |

因此，准确表述不是“先用低质量数据打基础”，而是：

> 先用大量达到最低正确性门槛的数据建立覆盖度，再用高标准数据校准最终行为。

## 推荐的实际配方

1. **Gold 起步**：构建约 1K 条人工确认的高质量数据，同时预留不参加训练的独立验证集。
2. **建立基线**：从相同 Base Model 训练 Gold-only 版本，确认任务可学、数据格式正确、训练管线有效。
3. **Silver 扩量**：生成或收集更多数据，通过规则、验证器、去重和人工抽检保证最低正确性。
4. **混合训练**：主体阶段以 Silver 提升覆盖，同时持续混入或上采样 Gold，避免行为遗忘。
5. **精品收尾**：降低学习率，提高 Gold、困难样本和真实失败案例权重，做短阶段校准。
6. **用评测决定**：比较 Gold-only、一次性混合、混合后 Gold 精修等方案，不凭口号选择。

Gold 不应该在第一阶段用完后消失。它既是早期实验的锚点，也是主体训练和末期校准中的稳定信号。

## 为什么高质量数据不能简单理解为“越少越好”

LIMA 使用 1,000 条精心选择的数据对一个已经充分预训练的 65B LLaMA 做 SFT，支持“强基座的很多能力已经在预训练中获得，SFT 可以主要负责对齐行为”的观点。但这不意味着：

- 任意规模的模型都只需要 1K；
- 专业知识、长尾场景和复杂工具调用也能靠 1K 覆盖；
- 1K 数据应当永远先于其他数据训练；
- 数据多样性不重要。

Alpaca 的 52K 合成指令与 LIMA 的基座、来源和评测设置不同，不能直接当作严格的质量—数量对照。AlpaGasus 从 Alpaca 中筛出约 9K 条数据后取得更好结果，说明盲目加入错误或无关样本可能产生负收益。另一方面，“Long Is More for Alignment”表明，回复长度这一简单指标就能筛出很强的 1K 基线，说明“质量”往往混合了正确性、信息密度、难度、覆盖度和风格一致性。

因此，“质量 > 数量 > 多样性”只能作为提醒，而不是普遍定律。更可靠的优先级是：

    正确性门槛
      -> 目标任务覆盖与多样性
      -> 有效信息密度和难度
      -> 在上述约束内扩大数量

## 业务 SOP 生成任务图的应用

针对“业务 SOP -> JSON 任务图”：

- **Gold 数据**：人工审核的复杂 SOP、异常分支、工具调用和恢复案例。
- **Silver 数据**：批量生成后通过程序验证的样本。
- **自动验证**：JSON Schema、DAG 无环性、节点引用完整性、工具参数类型和必要业务约束。
- **Reject 数据**：结构非法、节点悬空、逻辑冲突或答案错误的样本，直接排除。
- **训练调度**：Silver 扩展覆盖，Gold 持续重采样并在末期提高权重。
- **独立评测**：同时测图结构合法率和业务语义正确率，防止模型只学会输出合法 JSON。

程序验证器可以把大量合成数据从模糊的“低质量数据”转换成质量下限明确的 Silver 数据。

## 面试版表述

> SFT 可以先用少量 Gold 数据验证任务可学性并建立基线，再扩充经过清洗和验证的 Silver 数据提升覆盖度。正式训练时不会先把 Gold 用完再只训练低质数据，而是持续保留 Gold 采样，并在末期降低学习率、提高 Gold、困难样本和真实失败案例的权重，完成行为校准。错标数据应直接清洗，不能依赖最后的精品数据洗掉。
