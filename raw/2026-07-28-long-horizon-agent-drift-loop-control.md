### 00:00–00:20 问题

腾讯 Agent 二面必考工程题：怎么从工程层面解决长任务 Agent 的跑偏、绕路和死循环？

这题不考空泛理论，只看真实落地能力。面试官的核心追问是：用户只有一句话指令，Agent 却要运行十几步，凭什么牢牢记住目标、不跑偏？这道题专门筛选真正做过长任务 Agent 落地的人。

### 00:20–00:40 三个根因

长任务 Agent 失控不只是模型单次推理出错，而是三个问题叠加：

1. 上下文有限：原始目标被中间日志和步骤信息挤掉、遗忘。
2. 任务缺少规范拆解：任务越拆越散，逐步脱离主线。
3. 缺少逐步校验：小错误持续累积，没有被修正。

三者叠加后，Agent 最终会彻底跑偏并陷入死循环。

### 00:40–01:09 第一层：Planner

解决方案是一套可校验、可回滚、可观测的五层闭环工程机制。

规划层负责锁定主线，避免计划被随意修改。任务启动前一次性完成标准化拆解，生成固定子任务清单，每一步绑定明确、可验收的产出标准。整体计划先经过校验，确保所有子任务服务于原始目标。

每完成一个子任务，都要对照全局目标评分；验收不达标时，回滚并重做，防止隐性跑偏。

### 01:09–01:27 第二层：Memory

记忆层用结构化状态保存三类核心数据：原始目标、已执行步骤和关键产出。

同时动态精简上下文。模型推理时只加载当前步骤需要的信息，过滤冗余历史数据，避免核心目标被稀释，保证每一步执行仍锚定主线。

### 01:27–01:45 第三层：Critic

纠偏层负责定期校准航向、及时止损。

系统设置固定校验间隔，每隔若干步骤唤醒独立 Critic 模型，重新核对原始目标和当前进度。核心问题只有一个：“当前路径还在解决最初的问题吗？”

一旦判定路径偏离或属于无效绕路，立即终止异常分支，回滚到合法节点并重新规划。

### 01:45–02:03 第四层：硬规则兜底

通过工程硬规则提供极限保护：

- 同一步骤反复重试、出现循环卡顿时，直接判定异常并强制中断。
- token 消耗或执行步数接近预算上限时，立即停止执行。
- 停止后回滚到上一个 checkpoint。

硬性机制用于规避死循环、预算超限和无效绕路。

### 02:03–02:25 第五层：监控与评估

监控评估层让全链路可观测，并尝试在最终失败前识别跑偏。

线下用 benchmark 批量测试，提升任务完成率、降低目标偏离率。线上不能只看最终成功率，还要监控中间指标，例如：

- 每一步与目标的贴合度；
- 计划修改次数；
- 回滚次数；
- 重试次数。

Agent 跑偏通常不是最后一步突然发生，异常会提前暴露在中间轨迹数据中，因此可以预警并迭代优化。

### 02:25–02:39 总结

这道题本质上考察长任务 Agent 的工程架构能力。面试官需要的不是模型话术，而是一套可校验、可回滚、可观测、可兜底的标准化落地方案。
