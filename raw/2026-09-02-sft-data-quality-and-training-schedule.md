# SFT 数据质量、扩量与精品收尾的顺序辨析

## 用户问题

视频同时提出：

1. 从约 1K 条高质量 SFT 数据起步，根据效果逐步扩充到更大规模；
2. 清洗、去重和配平数据，并在训练末段混入精品数据“冲刺”；
3. 将其概括为“SFT 数据质量 > 数量 > 多样性，1K 精选就能跑通”。

用户据此询问：到底应该先用少量高质量数据做 SFT，再逐步增加质量较低的数据，还是先用较大规模的一般数据训练，最后用少量高质量数据精修？两种说法是否矛盾？

## 对话形成的核心结论

视频混合了两个不同层次的“顺序”：

- **数据集建设与实验迭代顺序**：先构建约 1K 条 Gold 数据，从同一 Base Model 出发建立小规模基线，验证任务是否可学、训练管线是否正确，再根据独立评测逐步增加经过清洗的数据。
- **同一个最终模型的训练调度顺序**：先用规模较大、质量达到最低门槛的 Silver 数据建立覆盖度；Gold 数据全程保留并重采样；末期降低学习率、提高 Gold、困难样本和失败案例的比例，校准最终行为。

因此，“1K 高质量起步”和“精品数据收尾”并不矛盾：前者主要描述数据工程与实验开发，后者描述正式训练的课程调度。

不推荐的做法是：同一个模型先在精品数据上收敛，随后只训练大量错标、冲突或格式混乱的数据。较晚的数据会持续提供梯度，可能稀释或覆盖此前形成的行为。

## 对“低质量”的进一步区分

“低质量”不能作为一个笼统类别：

- 表达不够精致，但答案基本正确：可以作为 Silver 数据扩大覆盖。
- 任务过于简单、重复或信息密度低：应该去重、降权或按任务配比使用。
- 答案错误、标注冲突、逻辑不成立、格式不合法：应清洗删除，不能依赖末期少量 Gold 数据修复。

更准确的说法是：先用大量“达到正确性门槛”的数据提升覆盖度，再用高标准数据校准；而不是“先用错误数据打基础”。

## 建议流程

1. 构建小规模 Gold 数据，并保留独立评测集。
2. 从相同 Base Model 训练 Gold-only 基线，确认任务可学且训练管线有效。
3. 扩充并自动/人工清洗 Silver 数据，检查正确性、去重和任务配比。
4. 主体训练阶段以 Silver 为主，同时持续混入或上采样 Gold，避免遗忘。
5. 末期降低学习率，提高 Gold、困难样本及线上失败案例权重。
6. 比较 Gold-only、统一混合、混合后 Gold 精修等方案，以独立验证集决定最终配方。

## LIMA、Alpaca 相关证据的适用边界

- LIMA 在已经充分预训练的 65B LLaMA 上使用 1,000 条精心策划的数据进行监督微调，主要支持“强基座的对齐可能只需要少量高质量示例”这一假设。它不能证明所有任务只需要 1K 数据，也没有直接回答数据先后顺序问题。
- Alpaca 使用 52K 条通过 Self-Instruct 风格生成的指令示例。由于基座、数据来源和评测设置不同，不能把 LIMA 与 Alpaca 简化为严格的“1K 高质量 vs. 52K 低质量”对照。
- AlpaGasus 从 Alpaca 52K 中筛选约 9K 条高质量数据并取得更好的评测结果，说明错误、无关和误导样本可能带来负收益，数据过滤有时比盲目扩量重要。
- “Long Is More for Alignment”发现，简单选取回复最长的 1K 条样本就是一个很强的基线，表明所谓数据质量往往同时包含信息密度、任务难度、覆盖范围和响应风格，不能用单一分数定义。

## 业务任务图示例

对于“业务 SOP → JSON 任务图”的 SFT：

- Gold：人工确认过的复杂 SOP、异常分支、工具调用和错误恢复案例。
- Silver：批量生成后通过 JSON Schema、DAG 无环性、节点引用、工具参数类型等程序校验的样本。
- Reject：结构非法、节点悬空、逻辑矛盾或答案错误的样本，直接清除。
- 训练：Silver 扩大场景覆盖，Gold 持续重采样并在末期提高权重；用未训练过的 Gold 测试集评估图合法率和业务语义正确率。
